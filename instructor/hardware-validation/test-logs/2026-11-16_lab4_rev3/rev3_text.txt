[Title] Lab 4
[Normal] Pick-and-Place: Teach Pendant Programming and MATLAB RTDE Control
[Normal] Accompanying MATLAB file(s):  UR_PickPlace_Lab.m, check_waypoints.p, URServerScript_Robotiq2F_PolyScopeX.script (runs on the robot)
[Heading 1] Overview
[Normal] In this lab you will program a UR e-series robot to pick up a cube and place it at a second location. You will do it twice: first with a program built on the Teach Pendant, and then from MATLAB over the RTDE connection that you set up in Lab 2.
[Normal] The overall objective is to record one set of waypoints, run the same task with both methods, and compare the two workflows.
[Heading 1] Learning Objectives
[List Bullet] Design a waypoint sequence for a pick-and-place task, including the approach and retract points, and record it with the Teach Pendant.
[List Bullet] Build and safely test a pick-and-place program on the Teach Pendant using joint moves (MoveJ), linear moves (MoveL) and gripper commands.
[List Bullet] Run the same sequence from MATLAB over RTDE, after verifying the connection against the Teach Pendant readout.
[List Bullet] Compare the two workflows and justify which one fits a given automation task.
[Heading 1] Background: Move Types and Approach Waypoints
[Normal] Every waypoint in this lab is recorded as six joint angles in degrees, in order from joint 1 (base) to joint 6 (wrist 3), exactly as the Teach Pendant displays them. These are the hardware angles theta_hw of Lab 3.
[Normal] The robot can travel between two waypoints in two ways. A joint move (MoveJ; the Joint Move node on the Teach Pendant) turns all six joints together so that they finish at the same time. It is the fastest way to travel, but the TCP follows a curved path. A linear move (MoveL; the Linear Move node) drives the TCP along a straight line. It is used for the short vertical moves down onto the cube and back up.
[Normal] A pick-and-place task therefore uses approach waypoints. The gripper first moves to a point directly above the cube, descends straight down, grips, and rises straight back up before it travels sideways. Without the approach waypoints the gripper would sweep in at an angle and push the cube or hit the table.
[Normal] UR_PickPlace_Lab.m uses the functions you ran in Lab 2 and requires the same server script to be running on the robot. Table 1 lists only what is new in this lab.
[Normal] Table 1: MATLAB functions and options that are new in this lab
  | Function | What is new
  | ur = urRTDEClient(robotIP, 'CobotName', 'universalUR3e') | CobotName names the robot model, so that MATLAB uses the dimensions of your robot.
  | sendJointConfigurationAndWait(ur, q, EndTime = t) | EndTime schedules the move to take t seconds.
  | pose = readCartesianPose(ur) | Returns a 1x6 vector: three orientation angles in radians, then the X, Y, Z position of the tool flange in meters (elements 4 to 6).
  | actuateGripper(ur, 'grip') and actuateGripper(ur, 'release') | Closes ('grip') or opens ('release') the Robotiq gripper.
  | t0 = tic and cycleTime = toc(t0) | The MATLAB stopwatch. tic starts a timer and toc(t0) returns the seconds elapsed since then. The script uses the pair to measure the cycle time.
[Normal] 
[Normal] You enter and read every angle in degrees. The script converts to and from radians.

[Heading 1] Part 1 - Define the Waypoints
[Normal] The task uses the six waypoints of Table 2. The robot visits them in this order: Ready, Pre-Pick, Pick (close the gripper), Retract, Pre-Place, Place (open the gripper), Pre-Place, Ready. The gripper is also opened once at Ready, before the first approach.
[Normal] Table 2: Waypoint definitions and the Teach Pendant node used to reach each one
  | Waypoint | Node | Definition
  | Ready | Joint Move | The start and end pose (Figure 1). Joints 2 to 6 must read −80, −80, −110, 90 and 0 degrees. Joint 1 is chosen by you.
  | Pre-Pick | Joint Move | The approach point: directly above the cube, 5 to 10 cm higher than Pick, with the same gripper orientation.
  | Pick | Linear Move | The open gripper fingers are on either side of the cube, just above the table. The gripper closes here.
  | Retract | Linear Move | Straight back up from Pick with the cube. This is the same pose as Pre-Pick, so it takes the same values.
  | Pre-Place | Joint Move | The approach point directly above the place location, 5 to 10 cm higher than Place.
  | Place | Linear Move | The cube rests on the place location. The gripper opens here.
[Normal]

[Normal] Figure 1: The Ready position (side view): shoulder and elbow bent, tool flange facing down. Joints 2 to 6 read −80, −80, −110, 90 and 0 degrees. Joint 1 (base) is your choice.
[Heading 2] Task 1: Record and Store the Waypoints
[Normal] You will write each pose in Table 3 for MATLAB and, while the robot is still there, store it as a node of a Teach Pendant program for Part 2.
[List Number] Set the speed slider to 25%. Tap the program name at the top of the screen, tap + Program, choose Create New Program, name it after your group, for example Lab4_Group1, and tap Confirm. Do not edit the Lab 2 program that holds the server script; you need it unchanged in Part 3.
[List Number] On the Move screen, set Relative To to base and check that Active TCP is your robot gripper TCP. Open the Joints tab and set joints 2 to 6 to exactly −80, −80, −110, 90 and 0 degrees, the Ready position of Figure 1. For each joint, tap its value field, type the target and tap Confirm. Then tap Move Here and hold Move to Position until the robot stops. The plus-minus buttons work as well. These five angles are required: they make the tool flange face straight down, which every later step relies on and check_waypoints.p verifies. Joint 1 (base) is the only free choice: turn it until the gripper is over the area between the two tape marks.

[List Number] Open the Robotiq gripper screen that the URCap adds to the Teach Pendant, activate the gripper (tap Scan if it is not detected) and open it. Put the cube on one of the two tape marks; that mark is the Pick location.
[List Number] From here on jog only with the +/- buttons of X, Y and Z on the Move tab, so that the gripper keeps pointing straight down. Jog until the open fingers are on either side of the cube and about 5 mm above the table, turning the cube if needed so that the fingers close on two flat faces. Close the gripper once to confirm the grasp, then open it again. Record and store this pose as Pick.
[List Number] Jog straight up along Z by 5 to 10 cm. Record and store this pose as Pre_Pick, and copy its values into the Retract row.
[List Number] Jog along X and Y until the gripper is above the place mark, then jog down to the Z of Pick. Record and store this pose as Place. Jog straight up by 5 to 10 cm, then record and store Pre_Place.
[List Number] Check Table 3: Pre_Pick must have the same X and Y as Pick to within about 2 mm, and Pre_Place the same X and Y as Place.

[Normal] The long moves between Ready, Pre_Pick and Pre_Place are joint moves because the shape of the path does not matter there. The four short moves next to the cube are linear so that the gripper travels vertically. The timer measures one cycle: it starts when the robot is at Ready with the gripper open and pauses when the robot is back at Ready. The MATLAB script times exactly the same interval, so the two cycle times in Table 5 can be compared.

[Heading 1] Part 3 - MATLAB RTDE Program
[Normal] UR_PickPlace_Lab.m runs the same eleven motion and gripper steps from MATLAB and times the same cycle with tic and toc. It connects to the robot, prints the current joint angles, and then moves through the waypoints you type into it. All of its moves are joint moves, and it opens and closes the gripper through the server script. Everything the script reports is printed in the MATLAB Command Window. Three safeguards are built in. Each waypoint starts as NaN, and the script stops before any motion while a NaN remains. It then runs check_waypoints.p, which computes where each waypoint puts the gripper and prints PASS or FAIL for eight checks, for example that Pre_Pick is directly above Pick and that the gripper points straight down. The robot does not move while any check fails. Finally the script asks you to type yes before the robot moves.

[Normal] Table 4 is the proof, before anything moves, that MATLAB is connected to this robot and reads its joints in the same order and units as the Teach Pendant. The joint angles should agree to within 0.1 degrees; the small difference is rounding. If they do not agree, make sure the robot did not move between the two readings. The positions are expected to differ in one way: MATLAB reports the tool flange and the Teach Pendant reports the TCP. Because the tool points straight down at Ready, X and Y should agree to within about 2 mm, and the MATLAB Z should be higher by the Z offset of the gripper TCP that you set in Lab 1 (the length of the gripper). If MATLAB reports a connection error instead of a readout, recheck the Ethernet cable and that ping 192.168.1.10 answers in a Windows Command Prompt.
[Heading 2] Task 5: Enter the Waypoints and Run
[List Number] In UR_PickPlace_Lab.m, find the section labeled TASK 5. Replace each nan(1,6) with the six joint angles of that waypoint from Table 3, in degrees and in order from joint 1 to joint 6. For example: pick_pos = [35.20 -98.41 -112.63 -59.02 90.05 35.11];. Fill in all six waypoints (ready_pos, pre_pick_pos, pick_pos, retract_pos, pre_place_pos, place_pos) and save the file.
[List Number] Leave moveEndTime = 3 unchanged. The script schedules every move by time, not by speed: at a 100% speed slider each move takes moveEndTime seconds, however short it is, and a lower slider stretches it (6 seconds at 50%, 12 seconds at 25%). Timed moves are slow and predictable, which suits a first program.
[List Number] Put the cube on the pick mark, as before every run, and check that the server script node is Green. The script opens the gripper itself after it reaches Ready.
[List Number] Set the speed slider to 25% for the first run, so that typed waypoints are tried slowly (about 12 seconds per move, under 2 minutes in total). Do not touch the slider while the script runs: the script waits for each move for the time that the slider implies.
[List Number] Run UR_PickPlace_Lab again and read the waypoint check that it prints in the MATLAB Command Window: eight numbered lines, each ending in PASS or FAIL, with the measured value below it. If any line shows FAIL, the robot will not move: correct the waypoint that the line names, in the script and in Table 3, and run again. If the pose itself is wrong, store it again on the Teach Pendant as in Task 3.
[List Number] When the Command Window shows ALL CHECKS PASS, confirm that the joint angles printed above the check match the Move screen, then type yes in the Command Window and press Enter. Any other answer cancels the run. Keep your hand near the e-stop and watch every move. The Command Window lists each of the eleven steps as it starts.
[List Number] To stop a run early without the e-stop, stop the program on the Teach Pendant. MATLAB then ends with an error within about a minute.
[List Number] When the sequence works at 25%, set the slider to 50% and run it once more (6 seconds per move, about 1 minute). When it finishes, the Command Window prints the cycle time. It is measured with tic and toc over the same interval as the Timer nodes of Task 3: from Ready with the gripper open until the robot is back at Ready. Record it in Table 5.
[Normal] If the script stops with an error:
[List Bullet] "Robot did not reach ...": the server script is not running, the robot is in a protective stop, or the speed slider is below 10%. Clear the stop on the Teach Pendant, press Play so that the node is Green again, and rerun the script.
[List Bullet] Before you rerun: if the robot stopped at Pick or Place, jog straight up clear of the table first, because the first move of the script goes directly to Ready. If the gripper still holds the cube, the script releases it at Ready: catch it and put it back on the pick mark.
[List Bullet] If the arm moves but the gripper does not, the program playing on the Teach Pendant is not the Robotiq server program. Load the correct program (Task 4, step 2).
